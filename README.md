# Streakify – Manual Testing Project

## 📌 Project Overview
Streakify is a web-based habit-tracking application that helps users create, manage, and track their daily habits. This project focuses on manually testing the application's functionality, usability, and reliability to identify defects and ensure that the application works as expected.

## 🎯 Project Objectives
- Understand the application workflow and functionality.
- Identify and validate application requirements.
- Prepare test scenarios and detailed test cases.
- Execute test cases and verify actual results against expected results.
- Identify, report, and track defects.
- Ensure the application's quality through manual testing.

## 🧪 Testing Scope

The following modules are covered in this project:

| Module | Testing Description |
|---|---|
| Register | Verify user registration functionality and field validations. |
| Home | Verify home page elements, navigation, and display. |
| Task | Verify habit/task creation, editing, deletion, and validation. |
| Scheduler | Verify scheduling and task-related functionalities. |
| Profile | Verify profile information and available profile functionalities. |

## 🛠️ Testing Types
- Functional Testing
- UI Testing
- Positive Testing
- Negative Testing
- Validation Testing
- Regression Testing

## 📂 Project Documents

The following testing documents are included in this repository:

| Document | Description |
|---|---|
| Test Scenarios | High-level scenarios covering application functionalities. |
| Test Cases | Detailed test steps, test data, expected results, and actual results. |
| Test Execution Report | Records test execution status and results. |
| Defect Report | Documents identified defects with severity, priority, and status. |

## 🔄 Testing Process

1. Requirement Analysis
2. Test Scenario Preparation
3. Test Case Design
4. Test Data Preparation
5. Test Execution
6. Defect Identification and Reporting
7. Test Reporting

## 🐞 Defect Reporting

Defects are documented with the following details:

- Defect ID
- Module
- Defect Title
- Steps to Reproduce
- Expected Result
- Actual Result
- Severity
- Priority
- Status

## 📊 Test Execution Status

Test execution results are maintained in the Test Execution Report. Each test case is assigned an appropriate status, such as:

- Pass
- Fail
- Blocked
- Not Executed

*Note: Only mark test cases as Pass or Fail after actual execution.*
